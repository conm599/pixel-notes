## 2. 用户流程（三个场景）

```
场景A 编辑器粘贴            场景B AI 对话框粘贴           场景C 二次及以后
Ctrl+V 图片 →               Ctrl+V 图片 →                Ctrl+V 图片 →
  ├ 未同意过？→ 弹《图床使用规范》卡片（同意/暂不/不再询问）
  │    同意 → 记 pn_users.img_consent → 继续
  │    暂不 → 本次跳过（不记忆），图片不插入，toast 说明
  │    不再询问（拒绝）→ 记拒绝，进设置可改
  ├ imgbridge.upload(file)
  │    取 CSRF（首次 GET tuchang api.php?action=csrf 播种）
  │    POST api.php?action=upload (img=file, folder_id=便签夹)
  │    POST api.php?action=share (id, hours=0)   ← 只调用不改分享机制
  │    组直链 https://<tuchang>/i.php?id=<id>&t=<token>
  ├ 成功 → 光标处插入 `![截图 2026-09-06](直链)` → md.js 渲染出图
  ├ 失败 → 降级：编辑器不插入 + toast 原因；AI 对话框保底走旧路径
  └ 全程并发窗口=1，同一粘贴去抖
```

## 3. 关键设计决策（每条都给了理由，可拍板改）

- **D1 链接形态用 `i.php?id=&t=` 直链，不用 s.php**：s.php 是 HTML 观看页没法嵌进 markdown；`i.php?id&t` 是原始图片流、token 即能力、可在图床随时撤销/改有效期，撤销后自动变 notfound 占位图（F8），便签侧零维护。
- **D2 上传走「浏览器直连图床 api.php 会话段」**：同 PHP 会话天然带登录态（F1），不用在便签服务器存图床 API Key，不经过便签服务器中转（省一跳、省内存、带宽不占两份）；与 dashboard.js 现行上传通道完全同构（F2）。
- **D3 目标文件夹 = 用户根级「便签」夹**：复制 `ensureApiFolder` 模式做 `ensureNotesFolder`，幂等（存在即返回）。用户在图床删了它也没事——下次粘贴自动重建。
- **D4 保留策略 = 存续不过期 + 删除后 30 天反悔期（v1.1 改）**：上传时 `expire_at=0`（存续）；**便签保存/删除便签时服务端 diff 图片引用**，对消失的引用调图床内部端点把对应图设 `expire_at=now+30d`（仅当当前为永久，不覆盖用户自设的更短有效期）；若引用重新出现（Ctrl+Z / 复活）则恢复永久。删除保存时前端 toast 明示「图床保留 30 天」。跨应用通信用**内部端点 + 共享密钥**（suite_cfg `internal_key`，两站同读 /var/www/suite-config.php；本地走 PSU_INTERNAL_KEY env），只允许操作调用方 uid 自己的图。
- **D5 同意机制 = 版本化政策 + 三态记忆**：`pn_users` 加 `img_consent` / `img_consent_at` / `img_policy_ver` 三列（ensureTables 自愈 ALTER）。政策文本存 `pn_settings`（管理页可改）+ 版本号；版本升级后再次弹窗确认。弹窗三选：**同意并继续 / 暂不（本次跳过，不记忆）/ 不再询问（记忆拒绝）**；设置菜单加「🖼 图床图片」项可随时改主意。
- **D6 失败降级原则：粘贴链路永不因图床死而断**：上传失败/超时（8s+重试1次）/CSRF 拿不到 → 编辑器场景 toast 失败原因、不插入内容；AI 对话框场景保底插入原 blob 逻辑（若未来 AI 支持看图）或占位文本。图床不可达不影响便签其它功能。
- **D7 图片命名**：`便签-<yyyymmdd-HHMMSS>`，避免「image.png」满天飞，图床里可辨识。
- **D8 隐私语义写进规范文案**：**链接即能力**——谁拿到 i.php 链接谁就能看图；便签若公开分享，图也公开。规范里必须加粗写明 + 指出可在图床撤销。

## 6. 安全与滥用防护

1. **CSRF**：上传/分享 POST 带会话段 csrf token；token 由新增只读 GET `action=csrf` 播种（no-store，不泄露多余信息）。
2. **限频**：上传 30 张/10 分钟（rate_check 文件守卫），防脚本刷配额。
3. **配额**：服务端 user_used/user_quota 硬校验已有（F2），前端 ImgBridge 把报错文案透传。
4. **内容安全**：GD 强制重编码 WebP 剥 EXIF 已有；魔数白名单已有；便签 CSP img-src https: 不放大攻击面（比现有 B 站/YouTube 嵌入宽得多——生产零改动）。
5. **隐私**：规范文案明示「链接即能力 + 公开便签=图公开 + 可随时在图床撤销」；同意时间与政策版本落库可审计。
6. **内容责任**：规范文案含「禁止违法内容，违规图床管理员可删」条款（图床本就有 adminws 管理与删除能力）。

## 7.1 全链路冗余清单（v1.1 新增，防奇葩用户专项）

| # | 奇葩场景 | 冗余对策 |
|---|---|---|
| 1 | **同一张图贴进多个便签，只删其中一个** | 释放前全库校验：`pn_notes WHERE user_id=? AND content LIKE '%token%'` 仍命中则**不**触发 30 天（token 是唯一键，LIKE 精确匹配 UUID） |
| 2 | **删除整个便签**（不是删图） | notes.php DELETE 同样对旧内容跑 diff——整删=全释放，同样过 §7.1-1 校验 |
| 3 | 删图后 Ctrl+Z 又保存回来 | 新增引用 diff → op=restore 恢复永久（没到 30 天就复活） |
| 4 | 用户已在图床手动设过有效期 | op=grace 只动 `expire_at=0` 的图；用户自设的更短/更长有效期不被覆盖 |
| 5 | 手改 markdown 里的 URL/伪造 token | diff 只认严格格式 `i.php?id=N&t=<uuid36>`；匹配不到的图不受影响；token 不可枚举（uuid_v4） |
| 6 | 并发保存（双标签页） | diff 基准=同一事务内读到的旧内容，最坏=漏释放一次（下次保存再触发），不会误删 |
| 7 | 内部端点被外人打 | `X-Internal-Key` 强校验 + 只能动调用 uid 自己的图 + 无 key 直接 403；本地/生产密钥分离 |
| 8 | 上传通道被脚本刷 | 限频 30/10min + 配额硬顶 + 魔数/GD 兜底已有 |
| 9 | i.php 图被删 | notfound.webp 占位（站长拍板：不新做同步） |
| 10 | 注销账号 | v1 图床图不联动删除（pn_uid 映射仍在）；标注为 P2 独立风险项 |
| 11 | 手机端无 paste | 按钮主入口（file input）三端统一，见 §2.1 |
