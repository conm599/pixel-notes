# 🚀 Pixel Suite 部署教程（小白版 · 从零到上线）

> 适用：**任何一台全新的 VPS**（Ubuntu 20/22、Debian 10+ 均可，1 核 1G 起步）。
> 全程大约 30 分钟。这套系统专门为「个人部署个人用」设计：**不需要手工建任何数据库表**，
> 建表、配置全部自动完成。遇到问题先看最底下的「常见翻车点」。

---

## 0. 这套系统是什么 & 部署完你会得到什么

Pixel Suite = **像素便签**（bianqian）+ **图床**（tuchang）双站合一：

- 账号互通：注册一次，两边都能用（首个注册的用户自动成为管理员）
- 图床支持截图/粘贴直传、公开分享、内容去重（相同图片只占一份磁盘）
- 便签支持 Markdown、AI 编辑/整理（可选，需要配 AI 接口）
- 管理后台：封禁用户、调整图床容量、邮箱验证开关、全部配置可视化修改

部署形态（本文档主推 **形态 A**，最简单）：

| 形态 | 地址样子 | 适合 |
|---|---|---|
| **A. 双域名**（推荐） | `notes.xxx.com` + `img.xxx.com` | 有域名、正经长期用 |
| B. 单域名子路径 | `notes.xxx.com` + `notes.xxx.com/tuchang/` | 只想用一个域名/一张证书 |
| C. 本地/无域名测试 | `http://IP:端口`，免 TLS | 本机试玩、纯 IPv6 测试机 |

---

## 1. 准备清单

| 东西 | 说明 |
|---|---|
| 一台 VPS | Ubuntu 20/22 或 Debian 10+，最低 1 核 1G，建议 20G+ 磁盘（存图） |
| 一个域名（形态 A/B 需要） | 去域名商后台加 2 条 A 记录指向 VPS IP：`notes` 和 `img` |
| 代码 | `git clone -b pixel-suite https://github.com/conm599/taowa-projects.git`（私有仓） |
| SSH 工具 | Windows 自带 `ssh` 命令，或 Tabby / Xshell 等 |

> 形态 C（纯 IP / 纯 IPv6 测试机）不需要域名，见附录 C。

---

## 2. 装环境（SSH 登录 VPS，一条命令复制粘贴）

```bash
apt update && apt install -y nginx mariadb-server php-fpm php-mysql php-gd php-mbstring php-curl php-cli php-zip certbot python3-certbot-nginx
systemctl enable --now nginx mariadb php7.4-fpm   # Ubuntu 22 是 php8.1-fpm，按实际版本名改
```

建数据库（**只需要建库和用户，表不用建**——程序首次访问自动建）：

```bash
mysql -e "CREATE DATABASE pixel_suite CHARACTER SET utf8mb4;"
mysql -e "CREATE USER 'pixel'@'localhost' IDENTIFIED BY '换成一个强密码';"
mysql -e "GRANT ALL PRIVILEGES ON pixel_suite.* TO 'pixel'@'localhost'; FLUSH PRIVILEGES;"
```

> 便签和图床**共用这一个库**（表前缀不同不会冲突）。记住这个密码，第 6 步要用。

---

## 3. 放代码

```bash
mkdir -p /var/www/hosting /var/www/tuchang
git clone -b pixel-suite https://github.com/conm599/taowa-projects.git /tmp/ps
cp -r /tmp/ps/bianqian/* /var/www/hosting/
cp -r /tmp/ps/tuchang/*   /var/www/tuchang/
chown -R www-data:www-data /var/www/hosting /var/www/tuchang
mkdir -p /var/www/private_img_store && chown www-data:www-data /var/www/private_img_store
```

---

## 4. 配 nginx

### 形态 A：双域名（把下面整个文件存为 `/etc/nginx/sites-available/pixel`）

```nginx
server {
    listen 80;
    server_name notes.xxx.com img.xxx.com;          # ← 换成你的两个域名
    location /.well-known/acme-challenge/ { root /var/www/html; }
    location / { return 301 https://$host$request_uri; }
}
server {
    listen 443 ssl http2;
    server_name notes.xxx.com;                       # ← 便签域名
    ssl_certificate     /etc/letsencrypt/live/notes.xxx.com/fullchain.pem;   # ← 第 5 步 certbot 会生成
    ssl_certificate_key /etc/letsencrypt/live/notes.xxx.com/privkey.pem;
    root /var/www/hosting;
    index index.php index.html;
    client_max_body_size 64m;
    location ~* \.(css|js|png|jpg|jpeg|gif|webp|svg|ico|woff2?|ttf|otf|mp3|mp4|ogg|webm|wav)$ {
        try_files $uri =404;
        expires 8h;
    }
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php7.4-fpm.sock;
        fastcgi_buffering off;
        fastcgi_read_timeout 300s;
    }
    # 图床子路径（可选：让 img 功能也能从 notes.xxx.com/tuchang/ 访问，删掉这块也不影响形态 A）
    location ^~ /tuchang/ {
        alias /var/www/tuchang/;
        index index.php;
        try_files $uri $uri/ =404;
        location ~ \.php$ {
            include snippets/fastcgi-php.conf;
            fastcgi_param SCRIPT_FILENAME $request_filename;
            fastcgi_pass unix:/run/php/php7.4-fpm.sock;
            fastcgi_buffering off;
            fastcgi_read_timeout 300s;
        }
    }
    location ^~ /config/ { deny all; }
    location ^~ /data/ { deny all; }
    location = /config.php { deny all; }
    location ~ /\.(?!well-known) { deny all; }
}
server {
    listen 443 ssl http2;
    server_name img.xxx.com;                         # ← 图床域名
    ssl_certificate     /etc/letsencrypt/live/notes.xxx.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/notes.xxx.com/privkey.pem;
    root /var/www/tuchang;
    index index.php index.html;
    client_max_body_size 16m;
    location ~* \.(css|js|png|jpg|jpeg|gif|webp|svg|ico|woff2?|ttf|otf)$ {
        try_files $uri =404;
        expires 8h;
    }
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php7.4-fpm.sock;
        fastcgi_buffering off;
        fastcgi_read_timeout 300s;
    }
    location ^~ /config/ { deny all; }
    location ^~ /data/ { deny all; }
    location = /config.php { deny all; }
    location ~ /\.(?!well-known) { deny all; }
}
```

启用（先删掉默认站避免冲突）：

```bash
rm -f /etc/nginx/sites-enabled/default
ln -sf /etc/nginx/sites-available/pixel /etc/nginx/sites-enabled/pixel
nginx -t && systemctl reload nginx
```

> 形态 B（单域名子路径）：上面的配置**已经包含**了——`notes.xxx.com/tuchang/` 这个
> location 就是图床的子路径入口，不需要 img 域名也能用全套图床。
> 形态 B 需要在第 6 步装完后，到 /admini 面板「站点域名」里把
> **图床完整URL** 填成 `https://notes.xxx.com/tuchang`（这样两站之间的跳转按钮才带路径）。

### 先用 HTTP 也能跑通（证书还没签时）

上面配置里引用了证书文件，还没签证书时 nginx 会启动失败。两个选择：

- **先注释掉两个 443 server 块**，只留 80 的跳转块 → 先跑通第 6、7 步，签完证书再解开；
- 或者直接先签证书（下一步），一次到位（推荐）。

---

## 5. 签 HTTPS 证书（certbot 自动搞定）

```bash
certbot --nginx -d notes.xxx.com -d img.xxx.com
```

certbot 会自动改好 nginx 的证书路径并配置自动续期。签完 `nginx -t && systemctl reload nginx`。

> **纯 IPv6 / 无域名机器**：Let's Encrypt 不给裸 IP 签证书。测试机可以：
> ① 用 acme.sh 申请 IP 短期证书（`--certificate-profile shortlived`，6 天自动续）；
> ② 或者临时免 TLS：给 php-fpm 池加 `env[PSU_LOCAL_HTTP] = 1` 并只用 80 端口（仅供测试）。

---

## 6. 打开网站 → 自动进入安装向导（本系统最省心的一步）

浏览器访问 `https://notes.xxx.com`——系统检测到还没配置，会**自动跳转到
`/admini/` 安装向导**。照着填：

| 分组 | 填什么 |
|---|---|
| 管理员账号 | 用户名 + 密码（≥8 位），**这是配置中心的密码**，记牢 |
| 站点域名 | 形态 A 填两个完整域名；形态 B 把「图床完整URL」填 `https://notes.xxx.com/tuchang` |
| 便签数据库 | 主机 localhost / 库名 pixel_suite / 用户 pixel / 密码=第 2 步那个 |
| 图床数据库 | **和便签填一样的**（共用一个库） |
| 邮件 SMTP | 有就填（注册要发验证码），没有可以先空着 |
| 图床常量 | 密令留空=与管理员密码相同；配额/上限默认即可；**注册邀请码和 cron 密钥已隐藏（无需填）** |

点「**完成安装并锁定**」→ 配置写入 `/var/www/suite-config.php`（webroot 外，nginx 不可下载）。

**这一步做完会发生什么：**

1. 自动跳转消失（再访问首页就是正常登录页）——自动路由只在「未安装」时生效一次；
2. 便签、图床的全部数据表**首次访问时自动创建**（不需要你跑任何 SQL）；
3. 图床建表也是全自动的（和便签同机制）。

---

## 7. 注册第一个账号（自动成为管理员）

访问 `https://notes.xxx.com` → 点此注册 → 填邮箱、用户名、密码：

- **第一个注册的账号自动成为管理员**（能看到管理面板和 AI 密钥管理）；
- SMTP 没配？去 /admini 面板「便签功能」把**邮箱验证开关设为 0**，
  注册就只需要邮箱+密码+图片验证码（同时「验证码登录/忘记密码」入口自动隐藏）；
- 想改用户名？登录后**点右上角抽屉栏里自己的用户名**即可；
- 图床入口：便签导航栏的「图床」按钮（或 `https://img.xxx.com` / 子路径 `/tuchang/`）。

管理员日常管理（都在便签的管理面板里）：用户列表/封禁/图床容量调整/用户搜索、
AI 接口与密钥发放、SMTP 配置。图床旧后台 `tuchang域名/adminws.php` 仍可用
（管理密令见 /admini 面板），高危的「删除用户」在那里。

## 8. 可选优化（都很短）

**BBR（提升跨境/高延迟线路的加载体验，零风险）：**

```bash
sysctl -w net.core.default_qdisc=fq
sysctl -w net.ipv4.tcp_congestion_control=bbr
printf 'net.core.default_qdisc=fq\nnet.ipv4.tcp_congestion_control=bbr\n' > /etc/sysctl.d/99-bbr.conf
```

**图片内容去重**：自动生效（相同图片只存一份磁盘，配额照常计）。
历史存量图片想合并省空间，跑一次：`php /var/www/tuchang/_dedup_scan.php`

**后期更新代码**：`tools/deploy-vps.py`（凭据走环境变量 PSU_HOST/PSU_USER/PSU_PASS），
自带远端 `php -l` 语法检查、sha256 校验、多文件批量。改 JS/CSS 记得 bump 引用 `?v=`。

**备份**：数据库 `mysqldump pixel_suite | gzip > backup.sql.gz`；图片目录
`/var/www/private_img_store/` 直接打包。/admini 面板也有自动备份开关。

---

## 9. 安全须知（个人部署也要看）

1. `suite-config.php`（含数据库密码和各站密令）**绝不能提交到 GitHub**；
2. `bianqian/_deploy.php` 含部署密令，只留私有仓和服务器，**绝不放公共仓**；
3. 生产环境把 admini 密码、图床密令设成强密码（安装后可在面板随时改）；
4. 数据库密码不要复用；服务器 SSH 关闭密码登录改密钥更好。

## 10. 常见翻车点

| 症状 | 原因与解法 |
|---|---|
| 访问一直跳 /admini/ | 还没完成安装向导，正常；装完自动消失 |
| 安装向导提交后报写入失败 | /var/www 目录权限不足时会自动落到 webroot 内（不影响使用）；想放到上一级就 `chown www-data /var/www` 后重装 |
| 图床页面 404（走子路径时） | nginx 的 /tuchang/ alias 块没加，或 admini 里「图床完整URL」没带 /tuchang 路径 |
| 分享链接打不开 | 优选域名配置成了不可达的域名；去 /admini 把「优选域名」清空即可只用当前域链接 |
| 上传提示太频繁 | 防滥用限流（30 张/10 分钟），批量传等一会儿再继续 |
| 图片验证码总说错误 | 验证码 5 分钟有效；免验证码模式请在 /admini「邮箱验证开关」设 0 |
| 忘记管理员密码 | /admini 登录页有密码入口；数据库在的话也可由其他管理员在面板改 |
| nginx 启动失败提示证书不存在 | 先签证书（第 5 步）或先注释 443 块 |
