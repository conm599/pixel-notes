# Pixel Notes AI 编辑协议（protocol）

> 唯一事实源：`api/ai.php`（服务端）与 `js/ai-direct.js`（浏览器直连）两端实现均以此为准。
> 改任何参数 / prompt / 话术：**先改本文件，再同步两端代码**，并把两边头部注释的版本号升到 `protocol.md vN`。

## v13（当前）

> v12→v13：**原生 tools 多厂商双模 + 全屏审阅页（站长定稿 2026-09-13）**。背景：v12 的文本协议 `<<<TOOL>>>` 仍要求模型「背格式」，多厂商（MiniMax/GLM/Kimi/DeepSeek/Gemini）表现不稳；替换块匹配失败只回一句「匹配不上」；结果确认是内嵌三 tab 弹窗，手机上无法逐处取舍。v13 做三件事：

**① 原生 function calling 优先，文本协议自动兜底（双模）**
- 统一走 OpenAI tools 格式（MiniMax/GLM/Kimi/DeepSeek 原生；Gemini 走官方 OpenAI 兼容端点），`tool_choice: "auto"`。
- 流式捕获 `delta.tool_calls` 分片（index → id/name/arguments 拼接），非流式解析 `message.tool_calls`；服务端与直连端同构。
- 上游拒绝 tools（HTTP 400/422，或错误信息含 tool 字样）→ 自动去掉 tools 重试一次 + 注入系统消息让模型改用文本协议 `<<<TOOL>>>{json}<<<END>>>`；文本协议分支保留。
- 工具集（原生调用名 / 文本协议 name 相同）：
  - `replace_text` {old_string, new_string}（兼容旧 {search, replace}）—— 默认首选；`new_string` 留空 = 删除该片段
  - `append_text` {text}
  - `write_note` {content}（兼容旧 `set_full_text` {text}）
  - `read_note` {id} / `list_folders` {path}（兼容旧 `list_folder`）
  - `ask_user` {questions[]}
  - `finish` {}
- 每轮必须至少调用一个工具；工具轮不消耗重试预算（≤8 轮，loopGuard >14 兜底防死循环）。

**② 替换匹配三阶段 + Aider 式失败回灌**
匹配顺序（任一阶段「唯一命中」才应用）：精确子串唯一 → 字符归一化（智能引号/破折号/省略号/NBSP；判据是归一化确实改变了原文且归一化后片段唯一）→ 逐行 trim 唯一 → 首尾锚点（≥3 行）唯一。
失败返回 `{ok:false, error:"not_found", did_you_mean_line, did_you_mean, similarity, current_tail, hint}`：给出原文中最相似片段 + 行号 + 相似度，提示「照抄 did_you_mean 修正后重试，已成功的改动不要再发」；`ambiguous` 返回出现次数与提示。**禁止因一次失败就改走整篇重写。**
提示词按 Cline/Roo 结构：角色（执行器非聊天）/ 工具铁律 / 工具清单 / 编辑规则 / 反跑偏（禁寒暄卖萌自称、禁客套开头、禁反问收尾、禁复述解释、工具外文字不入正文）/ 目标（只有 finish 或 ask_user 两种终止）。

**③ 全屏审阅页（前端）**
- 结果不再内嵌弹窗：`.ai-review` 全屏层，顶部 48px（取消 / 标题+待接受计数 / 全部接受）、中部逐 hunk 复选列表、底部 56px（拒绝全部 / 接受选中 k/n），375px 优先、PC 自适应。
- 自写行级 LCS（超 200 万格放弃逐行比对，退化为「整篇一处」）产出 `segs`/`hunks`；hunk 带上下 3 行、行号、-删/+增 统计；**按勾选情况重建全文**（勾中取新、未勾取旧），预览/源码视图实时反映当前勾选结果。
- 版本快照（上限 20）：写入编辑器前 push，「撤回这一步」可回退；撤回后回到可勾选状态。
- 状态机：`idle → thinking → streaming → tool_call → diff_ready → awaiting_confirm → applying → done | rejected | cancelled | error`，根节点 `data-state` 暴露。
- 生成中：工具行 `pending|running|success|error`（data-status 着色）；「停止」走 AbortController，**中断后保留已收内容**；流式滚动跟随阈值 48px。
- 错误归一成 kind（`auth|aborted|quota|context-limit|tool-failed|network|http|unknown`），以低调灰底行卡片展示（友好文案 + 重试），取代满屏红框。

**SSE 事件**（服务端 → 前端）：`phase{t}` / `delta{t}` / `tool{id,name,label,round}` / `tool_result{id,name,ok,brief}` / `done{...}`。

**④ 违规处理（v13.1，治「AI 一直在回答用户」）**
只要模型输出了内容却**没有任何工具调用**（原生 tool_calls 与文本协议 `<<<TOOL>>>` 都没有），即判为协议违规：
- 便签非空 → **打回重试**（追加系统消息要求立刻调用工具，最多 3 次），仍不执行则报错；**绝不把聊天/说明文字写进便签正文**。
- 便签为空 → 允许把该文本视为「从零创作」（空便签没有可污染的原文）。
- 工作副本已被工具改动过 → 直接用工作副本提交（改动绝不丢）。
提示词同步加硬：只输出文字而没有任何工具调用＝协议违规。

**⑤ 多轮对话（v13.2，聊天式）**
- **对话区可见**：AI 对话框内新增会话记录（`.ai-conv`），每接受一轮追加一条「你：<指令> / AI：已写入编辑器 · <具体改动>」。
- **接受即回到对话**：点「接受选中/全部接受」后审阅页自动关闭、直接回到输入框，**不需要任何「继续对话」按钮**；改完接着写下一句即可。
- 历史携带**具体改动**而非仅工具名：`history` 里 assistant 条目写成「（已写入便签："旧文本"→"新文本"）」；撤回会追加「（用户撤回了上一步改动）」。服务端注入在本轮指令之前，并带「已完成的改动不要重复执行」。
- 只有**真正被采纳**的轮次才记入历史（拒绝不留痕）；仅传摘要不传全文，避免 token 膨胀（≤12 条）。
- 退出：对话框底栏 `完成`（及右上 ✖关闭）= 结束会话并关闭整个 AI 页；再打开 = 新会话（历史与对话区清零）。
- 底栏另有 `撤回上一步`：把编辑器恢复到上一次 AI 写入前的内容，并记入会话上下文。

**⑥ 文本内嵌工具调用（v13.3，治「支持的模型被判为不支持」）**
很多 OpenAI 兼容端点（尤其聚合代理）不会把 tools 映射成原生 tool_calls，模型会按训练格式把调用**直接写在正文里**。现支持三种（含 `<minimax:tool_call>` 前缀）：
- `<tool_call>{"name":"x","arguments":{...}}</tool_call>`（Qwen/GLM；参数也可能平铺在顶层）
- `<tool_call><function=write_note>{json}</function></tool_call>`（站长实测截图）
- `<tool_call><invoke name="x"><parameter name="k">v</parameter></invoke></tool_call>`（MiniMax 系）
解析后与原生 tool_calls 走**同一条执行路径**（SSE 工具行 / 结果回喂 / finish / ask_user），正文里的散文不写入便签。
**降级判定收紧**：只有错误明确指向 tools 能力（`tool_choice` / `tools` / `tool use` / `function call` / 工具调用）才降级文本协议；旧的 `/tool/i` 见词就降级，会把支持工具的模型误判为不支持。
**安全网**：正文残留工具调用语法（解析失败）→ 判违规打回重试（≤3），**绝不写进便签**（哪怕便签为空）。

**⑦ 对话式 UI + 追加结果回喂（v13.5）**
AI 对话框按对话产品形态重做：用户气泡（右对齐，含昵称/时间）、AI 气泡（模型名/时间 + 可折叠工具卡片 + 结果说明 + 复制/重试动作），底部为输入条（输入框 + 发送钮），会话逐轮累积可滚动。
工具卡片头部显示「工具名 + 一句话结果」，展开显示**人类可读详情**（非原始 JSON）：
- `append_text` → 「追加的内容：<文本> —— 追加后的便签末尾 —— <便签尾部>」
- `replace_text` → 「已替换（匹配方式）—— 替换后的便签末尾 —— <便签尾部>」
- `write_note` → 「已整篇写入，共 N 字 —— 末尾 —— <便签尾部>」
- 失败 → 「错误：not_found + hint + 最相似片段（第 N 行）」
回喂模型的工具结果同步加厚：`current_tail` 由 120 字扩到 **600 字**，并新增 `appended`（本次追加内容）——**追加类操作后，模型能看到追加之后的便签末尾**，据此确认结果再继续；SSE `tool_result` 增发 `detail` 供卡片展开。

**回归**：diff 引擎单测 24 项、工具能力深度端到端 26 项（末尾追加/删除/修改/中间插入/精确修改 + 只回文字违规 + 出站 tools 形态 + 多轮历史）、浏览器审阅页 QA 25 项（聊天式续轮：接受后自动回对话、会话记录带具体改动、历史注入实测、撤回上一步、完成关页、违规不写正文），全绿。

## v12（历史）

> v11→v12：**编辑 Agent 化（站长定稿 2026-09-12）**。背景：① 上游模型经 RL 训练更擅长「带上下文的工具型 Agent」，而非「一次性格式输出机」；② 站长自定义风格偏好（猫娘人格等）应当被尊重，但一次性格式输出会让人格文字/寒暄直接污染便签正文。v12 把编辑模式改为轻量 Agent：

**工具集（文本改动只能经工具落地）**：
- `append_text` {text} —— 末尾追加完整 Markdown（站长习惯：优先追加、不动已有内容）
- `replace_text` {search, replace} —— 局部替换；`replace` 留空 = 纯删除。工具结果反馈 `not_found`（附 current_tail 摘要与提示）/ `ambiguous`（附出现次数与摘要），供模型自行修正锚点重试
- `set_full_text` {text} —— 整篇写入（仅整篇重写/翻译）
- `read_note` {id} / `list_folder` {path} —— 只读查看
- `ask_user` {questions[]} —— 澄清提问（替代 CLARIFY 块，多轮问答不计配额）
- `finish` —— 全部改完必须调用以提交结果

**机制**：
1. 服务端（或直连端）持有**工作副本**，工具在其上累积改动；多轮工具循环 ≤8 轮，**工具轮不消耗重试预算**（loopGuard 兜底防死循环）。
2. 模型在工具调用之外的散文只作进度展示（SSE phase），**永不写入便签**——人格/聊天文字与便签内容结构性隔离。
3. 兼容旧协议：SEARCH/REPLACE 块（作用于工作副本）与整篇正文输出仍被采纳。
4. 循环中止（工具轮打满/守卫触发）时，工作副本有改动即以工作副本提交，**改动绝不丢失**。
5. 服务端 api/ai.php 与直连端 js/ai-direct.js 同构；`PSU_AI_ALLOW_LOCAL=1` 为本地开发门（mock 上游联调，生产不设零影响）。

## v9（历史）

> v8→v9：**SEARCH 锚点最小化（治 token 浪费）+ `<<<SKIP>>>` 省略锚 + 传输层保活**。① **SEARCH 最小化硬规则**：SEARCH 只放定位所需的最短锚点（通常一句/一行 + 最多一行紧邻上下文），严禁为保命中复制整段/整节原文——旧规则「尽量短」约束力不足，模型常把大段原文原封不动塞进 SEARCH，改动几个字却输出上千 token；② **`<<<SKIP>>>` 省略锚**：要定位的位置在很长段落/列表中部时，SEARCH 写成「首行锚点」+ 一行 `<<<SKIP>>>` + 「尾行锚点」，引擎以「首锚起点、尾锚终点」圈定跨度整体替换为 REPLACE——SEARCH 恒 3 行，与跨度长度无关；③ 两级 SKIP 匹配（L1 首尾锚精确子串成对唯一 / L2 首锚首行+尾锚末行行尾空白归一成对唯一），唯一性与块隔离（doneRanges）标准与 v8 一致；④ SSE 心跳：模型 TTFT/长思考期间上游零字节，nginx `proxy_read_timeout`（默认 60s）会掐断客户端连接致前端「正在回复中」卡死，现 curl 进度回调每 15s 输一条 SSE 注释行（`: hb`，前端按无 event 块忽略）保持字节流动；⑤ 附带修复：aiChat 阶段 DNS 钉取误读未定义 `$base` 致 TOCTOU 防护静默失效，改为主机名同键读写。

### SKIP 块格式与匹配（v9 新增，两端一致）

```
<<<SEARCH>>>
首行锚点（原文逐字存在）
<<<SKIP>>>
尾行锚点（原文逐字存在）
<<<REPLACE>>>
（首尾锚点之间整个跨度改写后的完整内容，含首尾锚点的改写形态）
<<<END>>>
```

- 每个 SEARCH 最多一个 `<<<SKIP>>>`；多个 SKIP 的块直接失败，零个 SKIP 的块按普通块走三级匹配。
- L1：首尾锚都做精确子串匹配，枚举「头锚起点 × 其后尾锚终点」全部成对组合，过滤与 doneRanges 相交者后**唯一**才应用。
- L2：L1 失败后降级——取首锚的**首行**与尾锚的**末行**做行级 rtrim 归一（与 v4 行级归一同一空白集），行对唯一才应用，跨度 = 起始行行首到结束行行尾。
- REPLACE 必须是「整个跨度」改写后的完整内容（不是只写改动点），因为引擎会把整个跨度换掉。
- 全文重写（B）/澄清（C）路径的输出净化会剥掉孤儿 `<<<SKIP>>>` 标记。

## v8

> v7→v8：**替换块定位两项加固（治「第 14 条末句跑到第 16 条末尾」错位事故）**。① **精确级唯一性**：第 1 级精确匹配从「取首次出现」升级为「全文唯一出现才应用」，多处出现视为歧义、该块失败进入纠错重试（与第 2/3 级同一标准；SEARCH 句在重复句式文本中多次出现时，旧逻辑会替换到错误位置）；② **块隔离**：多块顺序应用时，每个替换块的 SEARCH 只在「原文未被前面块改动过的区域」匹配——前面块 REPLACE 输出的新文本不参与后续块的定位（旧逻辑后块可匹配进前块刚写入的区域，在同一位置反复改写，把锚句越搬越远）。

## v7

> v6→v7：**AI 整理升级为 SSE Agent 模式**（类 Claude Code）。① `action=classify` 从一次性 JSON 返回改为 SSE 流式（`phase`/`delta`/`tool`/`tool_result`/`done` 事件），前端聊天框实时显示 AI 的阶段进度、思考文本、工具调用卡片（工具名+参数+结果摘要）；② 整理侧 TOOL 上限从 5 次放宽到 20 次（防失控循环的保险丝，不是能力限制），prompt 鼓励"信息不够就查、查够为止"；③ 整理操作协议扩为 8 种 op（move/mkdir/rename/delete_folder/delete_note/sort_notes/color/pin），全部服务端程序校验+事务执行+undo 序列逆序精确还原。编辑侧 TOOL 行为不变（仍 5 次上限）。

### 整理 Agent 事件流（protocol v7 新增）

| SSE 事件 | data | 前端行为 |
|---|---|---|
| `phase` | `{"t":"🤖 开始分析…" / "🤔 第 N 轮思考…"}` | 更新 Agent 气泡阶段行 |
| `delta` | `{"t":"思考文本片段"}` | 流式追加到思考区（出现 `{` 或 `<<<` 即停止转发，协议原文不进聊天框） |
| `tool` | `{"name":"read_note","args":"#1","round":1}` | 新增工具卡片（🔧 工具名+参数） |
| `tool_result` | `{"name":"read_note","brief":"结果前300字…"}` | 结果摘要填进对应卡片 |
| `done` | `{"success":true,"plan":{"ops":[...]}}` | 收尾气泡为一句总结 + 弹预览面板 |

- 非流式降级：老浏览器 `aiApiStream` 自动整段读回重放，事件顺序不变。
- `delta` 转发熔断：accumulate 文本一旦出现 `{`（JSON 方案开头）或 `<<<`（工具块开头）就不再转发后续片段，避免把协议原文刷进用户聊天框。

## v6

## v5

> v4→v5：① **prompt「先问后做」互斥条款**——C 必须独立成轮（提问轮不得同时出正文），A/B 一经选择就不得再附任何提问 / 选项 / 寒暄（治「事后诸葛亮」：模型先编一版内容再反问「需要哪种风格？」）。② **流式输出**——`api/ai.php` 与 `js/ai-direct.js` 在调用上游时带 `stream:true`，逐 token 转发 SSE（`event: delta` 文本片段、`event: phase` 进度、`event: done` 最终结果）；前端实时把净化后的文本（剥协议标记）流式显示在预览框，结束再展示差异。上游不支持流式时自动降级为整段返回（结果不变，仅无实时预览），不报错。

### 工具调用块（TOOL block）

- **格式**：`<<<TOOL>>>` + 一行 JSON（`{"name":"工具名","参数键":"参数值"}`）+ `<<<END>>>`。AI 发起工具调用时，TOOL 块必须是输出的**全部内容**；不允许同时输出 A/B/C 编辑结果（工具结果返回前的中间轮不产内容）。
- **白名单只读工具**（两端实现必须一致）：
  | 工具名 | 作用 | 必需参数 |
  |---|---|---|
  | `list_folder` | 看指定文件夹（或主页）的子文件夹和便签清单 | `path`（完整路径，如 `"工作/项目A"`；主页填 `"主页"` 或 `""`） |
  | `read_note` | 看某条便签的完整内容 | `id`（便签 id，整数） |
- **轮数上限**：最多 5 轮工具调用；达到上限后强制要求 AI 产出最终 A/B/C 结果（禁止再用 TOOL）。
- **回喂格式**：工具结果以 `【工具结果】工具名\n{JSON 内容}` 的标准前缀追加到对话历史（user 角色），AI 继续下一轮推理。
- **权限**：两个工具都是只读（不允许修改数据）；只读当前登录用户自己的数据，服务端必须验证 `user_id`。
- **降级**：如果当前 AI 路径（直连或自有 Key）未实现工具调用，AI 忽略该段继续走现有 v5 流程（编辑正常进行，只是看不到文件夹内容）；不报错给用户。

> v4→v5：① **prompt「先问后做」互斥条款**——C 必须独立成轮（提问轮不得同时出正文），A/B 一经选择就不得再附任何提问 / 选项 / 寒暄（治「事后诸葛亮」：模型先编一版内容再反问「需要哪种风格？」）。② **流式输出**——`api/ai.php` 与 `js/ai-direct.js` 在调用上游时带 `stream:true`，逐 token 转发 SSE（`event: delta` 文本片段、`event: phase` 进度、`event: done` 最终结果）；前端实时把净化后的文本（剥协议标记）流式显示在预览框，结束再展示差异。上游不支持流式时自动降级为整段返回（结果不变，仅无实时预览），不报错。
> v3→v4：程序兜底取代纯模型守规（参考 Aider 的多级容错思路）。① **输出净化**：全文重写 / 整段重写路径返回前删除全部协议标记串（`<<<SEARCH>>>/<<<REPLACE>>>/<<<END>>>/<<<CLARIFY>>>`，大小写不敏感）并 trim，根治「全文混入孤儿标记」；② **三级宽容匹配**：SEARCH 精确匹配失败后，程序自动降级做「行尾空白归一」「全空白折叠归一」两级匹配（空白集为 `[ \t\r\n\f\v　]`，唯一命中才应用），大多数复述误差在程序层消化，不再进重试轮。
> v2→v3：空便签禁用 A 格式。空便签没有任何原文可供 SEARCH 匹配，模型一旦误用 A 必然三连败（对应线上「AI 指出的修改位置无法在原文中匹配」报错）。借鉴 OpenCode / Gemini CLI / Claude Code 等代理「编辑与写入分离」的设计：空文档只走写入路径——system prompt 明令空便签严禁 A；若模型仍输出替换块，两端代码兜底把全部 REPLACE 段拼成新全文（视同 B），不进入匹配重试。
> v1→v2：新增「澄清提问」——指令有歧义 / 缺关键信息时，AI 用 `<<<CLARIFY>>>` 块提问，用户回答后带历史多轮继续，直到信息足够再执行编辑。分段时间不消耗配额（成功才扣）。

### 输入约束

| 项 | 上限 |
|---|---|
| 便签内容 | 30000 字 |
| 编辑指令 | 2000 字 |
| 澄清轮数 | 不设硬上限（每轮需用户手动回答，人工熔断；服务端仅保留 10 轮防滥用截断） |
| 每轮问题数 | 最多 3 个 |

> 空便签**不再前置拦截**，但**严禁 A 格式**（没有原文可 SEARCH）：创作类指令由 B 格式直接创作；编辑类指令拿不准时由澄清提问（C）确认意图。硬性规则第 6 条与之对应；模型误用 A 时由「空便签兜底」接管。

### 调用参数

| 项 | 值 | 说明 |
|---|---|---|
| temperature | 0.1 | 低随机性，保证 SEARCH/REPLACE 精确匹配 |
| max_tokens（单发） | 16000 | 全文单次处理 |
| max_tokens（分段） | 16000 | 长文切块逐段，两端必须一致，避免截断导致结果不一致 |
| 自纠错轮数（单发） | 最多 3 轮 | 空内容 / SEARCH 匹配失败时带上下文重试 |
| 自纠错轮数（分段） | 每段最多 2 轮 | 同上 |

### 长文分段

| 项 | 值 |
|---|---|
| 触发阈值 | 内容 > 4500 字 |
| 块大小 | 3000 字 |
| 切块规则 | 优先段落 / 换行边界，块必须是原文精确子串 |
| 每段附大纲 | 各段首行前 24 字，编号列表（`1. xxx`） |

分段模式在 system prompt 追加：

```
【分段模式】这是一篇长文，已分 N 段，你只处理「本段内容」这一个段。SEARCH 段必须逐字复制自「本段内容」。若本段完全无需修改，只输出四个字：本段无需修改。
```

### 输出协议

- 局部修改（默认首选）：`<<<SEARCH>>>` + 原文逐字段 + `<<<REPLACE>>>` + 修改后文字 + `<<<END>>>`，可有多个，SEARCH 尽量短且在全文中唯一。
- 全文重写：仅当指令要求整体重构 / 全文翻译 / 全文总结 / 从零创作时，直接输出完整新全文。
- **澄清提问（新增，优先级最高）**：存在**任何**疑问就必须提问——指令有歧义 / 缺关键信息（主题、风格、长度、格式、语言等）/ 无法确定用户要改什么 / 对用户意图没有把握时，一律先提问，**不能猜、不能编造、不能自行假设**，宁可多问一句，不可错改一字：

```
<<<CLARIFY>>>
（一个问题一行，最多 3 个，简洁具体，不重复已问过的问题）
<<<END>>>
```

- 输出中同时存在 CLARIFY 与 SEARCH 时，CLARIFY 优先，仅返回 CLARIFY。
- 硬性规则：禁止删除 / 改写 / 移动用户已有的链接、URL、HTML 标签、图片 / 音视频 / iframe 嵌入、代码块；没让改的部分一字不动；不输出解释 / 前言 / 结束语；不用代码围栏包裹整体输出。
- **图片尺寸模板**：图片默认撑满便签可用宽度。用户要求调整某张图片显示大小时，必须用 HTML 标签加 width 数字属性：固定宽度 `<img src="图片URL" width="360">`、按容器比例 `<img src="图片URL" width="50%">`。禁止 style 属性 / `width="300px"` 带 px 写法 / div 包裹缩放（渲染端属性白名单会剥掉，不生效）；Markdown `![alt](url)` 写法无法指定尺寸。调整尺寸时只加/改 width，URL 与其余内容不动（服务端 ai.php 与直连 ai-direct.js 提示词已同步）。
- 便签标题不在 AI 负责范围，只编辑正文。

### 澄清提问（多轮流程）

1. AI 输出 `<<<CLARIFY>>>` 块 → 服务端 / 直连端把问题数组返回前端，**本次请求不计配额**。
2. 前端逐题展示输入框，用户提交回答 → 携带 `clarifyRounds=[{q,a},...]` 重新发起同一请求（内容 / 指令 / 模式不变）。AI 问题下方另有「其他补充（可选）」输入框，用户填写的内容会并入本轮最后一问的回答（前缀 `【其他补充】`），作为额外上下文注入对话。
3. 服务端把历史问答注入对话（assistant 提问块 + user 回答），AI 见过前文不重复问。
4. 轮数不限：AI 拿不准就一直问下去，每轮都需用户手动提交回答才会继续，用户随时可点取消退出；前端显示「第 N 轮问询」递增计数。
5. 澄清轮期间返回的 usage 为当前用量，不累加；**只有最终编辑成功才扣 1 次配额**。

### 无需修改判定

输出不含 `<<<SEARCH>>>` 且命中 `无需修改|没有需要|不涉及修改|不用修改` → 跳过该段。

### 空内容重试话术（两端一致）

- assistant：`（上一轮返回为空）`
- 分段 user：`你上一轮返回了空内容，请重新处理本段。`
- 单发 user：`你上一轮返回了空内容，请重新按格式输出编辑结果。`

### 纠错反馈（SEARCH 匹配失败，两端一致）

- 单发（带失败 SEARCH 预览：前 20 字 × 最多 3 个，以 `/` 分隔）：

```
你上一轮输出的替换块全部无法匹配原文（共 N 个）。SEARCH 段必须从【当前便签内容】中逐字精确复制（包括空格、换行、标点、Markdown 符号），禁止凭记忆复述。你上轮的 SEARCH 段开头分别是：「…」。请重新输出替换块完成原指令：<指令>
```

- 分段：

```
你输出的替换块无法在「本段内容」中精确匹配。SEARCH 段必须逐字复制本段原文（含空格、换行、标点），请重新输出。
```

### 空便签兜底（两端一致）

便签正文 trim 后为空且模型误输出 A 格式替换块时，**不做匹配重试**：把全部 REPLACE 段按顺序以空行（`\n\n`）拼接为新全文，按 B（全文重写，`mode=full`）返回成功。仅当拼接结果仍为空时才走原有的失败 / 重试路径。

### 输出净化（两端一致）

全文重写（单发 B 格式）与整段重写（分段无块路径）返回前，对输出文本执行：删除全部协议标记串 `<<<SEARCH>>>`、`<<<REPLACE>>>`、`<<<END>>>`、`<<<CLARIFY>>>`（大小写不敏感，标记本身删除、内容保留），然后 trim。澄清解析与替换块提取必须在净化**之前**基于原始输出进行。

### 三级宽容匹配（两端一致，v8 加固）

替换块的 SEARCH 段在原文中定位时，按顺序尝试三级匹配，任一级成功即应用替换（替换文本保持原文侧的真实字符，仅用于定位）：

1. **精确匹配**：`strpos` 子串查找，**全文唯一出现才应用**（多处出现视为歧义、该块失败）。
2. **行尾空白归一匹配**：原文与 SEARCH 均按行拆分、每行去除行尾空白（空白集 `[ \t　]`）后按行拼接比较；在原文中按行滑窗查找。
3. **全空白折叠归一匹配**：空白序列（空白集 `[ \t\r\n\f\v　]`）折叠为单个空格并去除首尾空格后比较；同样按行滑窗查找。

约束：**三级全部要求全文唯一命中**才应用（命中 0 处或多处均视为失败，避免错改）；滑窗内层循环在归一化长度超过 SEARCH 归一化长度时提前终止（归一化长度随行数单调不减）。三级全部失败才把该块计入失败、进入纠错重试。

### 块隔离（v8 新增，两端一致）

同一次输出含多个替换块时，块按出现顺序逐个应用，但**每个块的 SEARCH 只允许在「尚未被任何前序块的 REPLACE 覆盖的原文区域」内定位**。实现方式：维护已替换区间列表，后块命中位置落在已替换区间内即视为无效命中（多处有效命中仍按唯一性规则失败）。效果：AI 的后一个块不可能改写前一个块刚输出的新文本，杜绝锚句被逐块搬迁的错位链。

### 流式输出（两端一致）

调用上游时请求体带 `stream: true`（流式可用时；不可用则整段返回，结果不变）。

- 服务端 `api/ai.php`：响应头 `Content-Type: text/event-stream`、`X-Accel-Buffering: no`、`Cache-Control: no-store`，预检失败（未登录 / 配额 / 参数）仍走普通 JSON。处理阶段发出三类 SSE 事件：
  - `event: delta` `data: {"t":"片段"}`：上游 token 片段（原始，含协议标记）逐段转发；
  - `event: phase` `data: {"t":"🧩 长文分段：第 X/N 段…"}`：阶段进度；
  - `event: done` `data: {结果对象}`：最终结果（与原 JSON 结构完全一致：`success/content/mode/applied/failed/usage/need_clarify/questions/clarifyRounds/message`）。
- 直连端 `js/ai-direct.js`：`callOnce` 用 `ReadableStream` 读取上游 SSE，`delta.content` 调 `onDelta`、阶段调 `onPhase`、最终返回 `{ok,text}` 结构不变。
- 前端：流式期间把累积文本剥协议标记后实时显示在 `.ai-stream` 预览框（自动滚到底），`done` 后走原有结果展示流程。流式不可用时静默降级（无预览，结果照常）。

### prompt「先问后做」互斥条款（两端 system prompt 一致）

C 是独立的一轮输出：提问那一轮绝不能同时生成任何正文；反过来，一旦选择 A 或 B，输出里就绝不能再出现任何提问、确认、选项或结尾寒暄（如「需要哪种风格？」「有其他想法可补充」一律禁止）。拿不准就先用 C 问清楚，问完再动手，绝不许先编一版内容再附一句反问。硬性规则第 7 条与之对应。
